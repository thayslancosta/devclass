# DevClass — Technical Overview

This document summarizes the boundaries and core data flow of the academic management application.

## Request flow

1. A teacher authenticates through the Express REST API and receives a JWT.
2. Protected GraphQL operations derive the teacher identity from the token.
3. The teacher manages academic periods, classes, students and enrollments.
4. Lessons and skill-based daily records store evidence for the selected class and enrollment.
5. Daily messages and partial or final feedbacks can be written manually or generated by an explicit request to the OpenAI service.
6. The teacher reviews the result, communicates it through an external channel, and confirms delivery manually in DevClass.

The application does **not** automatically send emails or WhatsApp messages.

## Architecture and persistence

- The React frontend uses REST for authentication and administration and GraphQL for pedagogical records.
- The backend is built with Node.js, Express, Apollo Server, GraphQL and Mongoose.
- MongoDB stores academic data. Ownership checks and status/archive fields support teacher isolation and historical records.

## Validation boundaries

The project has local frontend tests, lint and build scripts. End-to-end browser flows, real MongoDB integration and external AI calls require additional environment-specific validation; production readiness is not claimed.
